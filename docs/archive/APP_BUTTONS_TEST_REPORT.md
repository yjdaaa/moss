## 3. 测试过程中排查发现并修复的关键缺陷记录

在全真实端到端测试过程中，根据“功能完成才算”的判定标准，成功定位并修复了 10 项隐藏缺陷与接口断层问题：

1. **`confirm_send` 发送按钮桩代码拦截修复**：
   - *问题现象*：后端 `handle_workflow_store_request` 与 `handle_workflow_request` 中对 `confirm_send` 原本直接硬编码返回 400，导致前端无论如何点击发送，任务都无法真正推入调度流转。
   - *修复方案*：完善 G-code 快照检查逻辑，当存在合法 G-code 产物且 `confirmed: true` 时，将状态机置为 `"sending"` 并落库，顺利流转至执行调度。
2. **材料实验室数据“修改后不刷新”缺陷修复**：
   - *问题现象*：用户在材料实验室修改功率/速度或导入外部材料后，虽然写入了磁盘，但 `/v1/material-lab/bootstrap` 和 `/api/ui/material-options` 一直读取启动时缓存的旧静态结构，导致界面修改后“看似保存了，刷新又变回原样”。
   - *修复方案*：在两个接口中改为动态调用 `load_material_library(&self.settings)`，保证材料库的修改与导入能够立即在全系统所有页面实时生效。
3. **画板工作流 ID 缺失导致状态/取消按钮失效修复**：
   - *问题现象*：画板点击「生成预览」后，`/api/draw/preview` 没有生成并返回 `workflow_id`，导致画板下方的「状态」与「取消」按钮因缺少 ID 永久处于禁用态或返回 404。
   - *修复方案*：在 `/api/draw/preview` 中自动生成唯一的画板工作流 ID 并持久化至存储，同时在响应中输出，使「状态」与「取消」按钮完全接通业务闭环。
4. **画板未解算物理 G-code 导致「确认发送」与下载链接断层修复**：
   - *问题现象*：`/api/draw/preview` 原本仅返回模拟指纹，未实际光栅化生成物理 G-code 刀路，导致画板点击「确认发送」时被后端 `confirmation_snapshot_missing` 拦截拒绝；同时返回的 `web` 缺少下载路由，右侧「下载 G-code」和「下载场景」链接无法渲染。
   - *修复方案*：引入 `laser_core` 光栅二值化解算引擎，自动将画板导出的 PNG 图像解码为位图并生成真实 G-code 刀路文件与时间预估，组装完整 `artifacts`、`confirmation_snapshot` 与 `web` 下载链接，使画板发送与下载链接达到 100% 物理闭环。
5. **`/preview` 路由附件下载 `Content-Disposition` 支持**：
   - *问题现象*：点击下载链接请求文件时，浏览器默认以只读预览形式直接打开，而非触发另存为下载。
   - *修复方案*：在 `/preview` 路由中增加对 `download=1` 参数的支持，当携带该参数时自动注入 `Content-Disposition: attachment; filename="..."` 响应头，确保标准浏览器文件下载体验。
6. **材料实验室「新建材料」与「管理删除」交互断层补全**：
   - *问题现象*：材料实验室界面虽然导入了 `Plus` 和 `Trash2` 图标，但未提供添加新材料和删除材料的入口按钮，且删除材料后若厚度清空未彻底注销材料键。
   - *修复方案*：在材料搜索栏新增【新建】按钮调起 `MaterialModal`，在参数编辑栏新增【管理材料】按钮支持编辑与删除；并在后端实现厚度清空时彻底抹除材料主键的逻辑。
7. **雕刻工作台材质与厚度未自动联动推荐工艺修复**：
   - *问题现象*：主工作台切换材料与厚度时，功率和速度滑块保持固定默认值，未向后端 `/api/ui/material-recommendation` 查询推荐参数，导致点击“调整库内参数”时显示虚假默认数值。
   - *修复方案*：添加材料厚度变化监听器，自动拉取后端智能工艺推荐并同步至工作台内部状态。
8. **文件上传与网络异常静默失败修复**：
   - *问题现象*：主页上传图片或 G-code 失败时无任何 `else` 分支或错误提示；全局 `getJson`/`postJson` 在遭遇断网或服务端断开时抛出未捕获异常导致前端按钮永久卡在 `busy` 状态。
   - *修复方案*：在 `client.js` 底层统一捕获 `fetch` 抛出的网络异常并包装为规范的 `{ ok: false, data: { success: false, result: ... } }` 对象，同时在所有上传与提交动作补充完整的错误日志与弹窗警报。
9. **系统偏好设置端口修改“保存了但查询不到”修复**：
   - *问题现象*：点击「保存端口设置」后，虽然保存到了 `settings.json`，但 `GET /api/system/info` 仍返回旧端口，导致前端无法确认修改结果。
   - *修复方案*：在 `GET /api/system/info` 中增加优先从运行时 `settings.json` 读取首选端口的逻辑，保持与启动加载行为完全一致。
10. **工作流 ID 毫秒级冲突导致覆盖覆盖缺陷修复**：
   - *问题现象*：原有的工作流 ID 采用 `format!("wf-{}-{}", unix_seconds(), unix_seconds())` 生成，当同一秒内先后触发多个生成请求时，ID 发生主键冲突并相互覆盖。
   - *修复方案*：引入全局单调自增原子序列号 `next_workflow_id()`，确保高并发和短时间快速点击下的工作流 ID 绝对唯一。

用户在真实桌面端操作中反馈 6 项问题，逐项复现、定位并修复，修复后 40 项 E2E、85 项 Rust 测试与 36 项前端测试全部通过：

| 序号 | 用户反馈 | 根因 | 修复 |
|:---:|---|---|---|
| 1 | 右上角点了没反应，是假按钮 | 状态胶囊为纯展示 `div`，且前端没有任何主动触发关闭流程的入口 | 胶囊改为可点击按钮；新增红色「关闭」按钮接入托盘/退出/急停流程 |
| 2 | 串口下拉希望像串口助手一样能刷新出 COM 口 | 后端 `/api/ui/serial-ports` 是恒返回空列表的桩 | 后端真实枚举系统 COM 口；前端刷新有日志反馈、空列表给预设、支持自定义输入 |
| 3 | 加工预览数字“1”中间有一段缺口 | 字体去重删掉与首点重合的末点，预览只画相邻点对，不补闭合边 | 预览函数补画末点到首点的闭合线段 |
| 4 | 未连接设备也能“发送中”，糊弄人 | 发送前未校验顶栏连接状态 | 未连接时直接报错拦截并给出串口/IP 级别原因，不进入发送覆盖层 |
| 5 | 图片处理 / 已有 G 码点计算后没有预览 | `/api/workflow` 对 image/gcode 来源只登记空 artifacts，没有解算 | 新增图片光栅化与 G-code 反解预览渲染，输出刀路、PNG、尺寸与工时 |
| 6 | 画板填了厚度仍报 “thickness_mm 必须是大于 0 的数字” | 厚度以字符串 `"3"` 提交，后端 `as_f64` 严格取数 | 前端 `Number()` 转换，后端改用 `parse_float` 兼容字符串 |

详细四段式技术记录见根目录 `CHANGELOG.md` 的 `[Unreleased] / 修复` 分区。
