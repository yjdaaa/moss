# 项目全局功能白话字典

适用项目：MOSS（小智本地能力助手，Rust 版）。2026-09-21 按当前代码核对：Python 版的摄像头、智能家居、桌面 GUI 自动化与语音图片引擎已移除，相关条目已删除或改写。

本文档用于团队培训、交接、销售演示、运营说明和长期维护。目标是让没有专业背景的人，也能快速看懂这个项目能做什么、用户怎么用、哪些地方有风险、以后新增功能时该怎么维护说明。

---

### 2026-10-10 安全修补

撤销设备后，旧连接不能继续发起操作，尚未使用的审批也作废；但机器已经收到的指令不能靠撤销收回。查询状态失败时显示“状态未知”并继续尝试，不把它当成停机，工作台与审批覆盖层保留急停。语音不会只因听到半句“停止”就抢先执行停止通道，而是在完整短句识别后处理。语音计算改为独立处理；不同设备的同编号请求不混用审批，内容改变则要求重新发起。以上不替代实体急停，真人和真实硬件仍需另行验收。

### 2026-10-11 NV14 本地音乐（软件阶段）

在 MOSS 桌面“内置语音 → 本地音乐”中，用户可主动选择本机音乐文件夹，并决定是否启用。默认关闭，不自动读取家目录、下载或上传歌曲。启用后语音可按歌名选歌，重名先询问；模型不能指定任意文件路径或网址。播放使用原有24kHz Opus声音通道；切歌、插话、撤销设备会清理旧音频，歌词和歌曲内容不进入聊天记忆。

合成 WAV 解码、假小智点歌/abort/撤销、桌面配置及主窗口专用权限已经通过软件测试。真实设备声音质量、长曲资源占用、MP3/FLAC/Ogg 多格式音频及实际安装仍需后续验收。音乐测试不连接激光机，真实 Codex 仍禁用。

### 2026-10-10 NV12 视觉图片理解（软件阶段；2026-10-16 增加“用对话大模型看图”开关）

MOSS 新增默认关闭的视觉图片上传与解释服务：用户在桌面设置独立视觉模型和密钥后，**已授权的小智设备如果固件支持主动上传图片**，可以把一张 PNG/JPEG 发到 MOSS，交给所配置的视觉模型解释。2026-10-16 起还可以在视觉卡勾选“用当前对话大模型看照片（多模态）”，把照片交给主对话模型（需该模型支持看图），不再需要单独的视觉模型；另有“把这张照片留在对话上下文里”开关（默认关闭），打开后这张图会作为一条多模态消息留在本次会话的对话上下文，后续追问可以直接引用（只在内存、随历史截断丢弃、不落盘，且每轮都会重发给模型、费用更高）。MOSS 不会自动开启电脑或小智摄像头，不保存原始图片，也不会让视觉模型直接执行激光、材料或其他设备动作。图片请求要验证设备身份和当前授权，限制图片体积、像素及并发；模型可能涉及第三方费用。软件模拟测试与构建不代表真实摄像头、固件或模型已通过验收；这些保留到最终统一测试。

### 2026-10-15 NV13 本机编程 Agent（用户开启）

对小智说一句话，就能让**本机的**官方 Codex 或 Claude Code 在你指定的工作目录里干活（可以新建和修改该目录里的文件），不用自己开终端。默认关闭，全部条件都由用户掌握：先在语音中心的“功能扩展 → Claude Code / Codex”打开开关，并填好工作目录与至少一个 CLI 路径；必须同时开启严格模式（`.env` 的 `MOSS_FUSION_STRICT=1`），否则 MOSS 不提供这个工具；每次运行都会在电脑上弹出审批卡，批准了才启动，运行中可以在卡片里停止，进程树会一起结束。任务结束、失败、超时、被停止都会留下带短错误码的记录，结果未知的不会自动重跑。

需要知道的边界：Agent 用的是你自己已登录的 CLI 账号，会产生模型费用；**它在 Windows 上挡不住读取工作目录以外的文件**（CLI 自己的沙箱限制不了），所以工作目录请挑一个可以公开给模型看的目录，不要指向 MOSS 数据目录或密钥目录。真实账号与实机体验按 HW-19 验收。

### 2026-10-15 NV17 固件升级（OTA，逐台确认推送）

把自己编译的 ESP32 **应用**固件（编译输出里的 `.bin`，不是整片烧录包）导入“安全设置窗口 → 固件升级（OTA）”，然后**一台一台**选设备确认推送。设备下次开机检查更新时会自动下载并刷写，刷完重启上报新版本，记录才变成“已升级”——**下载完成不等于刷写成功**。推送只对已允许的设备、只对版本确实更新的固件有效，链接是一次性的（24 小时到期，取消或上报后立刻失效），并且只接受这台设备最近一次上报的来源地址下载。

安全提醒：刷固件会真的改设备，可能刷坏；推送前确认板型匹配，并准备好能串口重刷的兜底方案。真实刷写按 HW-20 单独授权验收。

### 一、核心业务主线（用户是怎么用这个产品的）

Rust / FluidNC 更新：完整任务要求机器空闲且无急停/故障/门开信号；设备功率标尺不是 1000 时上位机自动按比例换算，不改固件配置。发送进度 100% 后仍可能等待机器执行完成。
软件通过执行同步和 Idle 状态核验后才报完成，0x18 是软件复位请求，不是物理急停。
详见 [翼宿适配说明](../laser/fluidnc-yisu-v1.md)。

Jev 加工反馈：设置中只使用 OpenRouter 的 `typesafe/jev-1.13`。主页和画板的任务反馈区可查看原反馈、判断来源、建议与已采用参数。采用建议只生成新预览，仍需单独确认加工；不会直接控制机器。不明确的反馈不调整，服务不可用时明确标记本地规则。旧任务缺少实际参数时需要补充信息，不能猜值自动采用。

1. 用户对小智设备说出需求，例如“打开微信”“生成一张文字图片”“看看激光机状态”“帮我准备雕刻这张图”。

2. 小智把用户的话交给本地助手，本地助手判断这件事应该由电脑、激光机，还是文字图片生成能力来完成。

3. 如果是低风险任务，例如打开软件、打开网页、生成文件、查询状态，系统会直接处理并把结果告诉用户。

4. 如果是高风险任务，例如启动激光、切割材料、让机器移动、修改机器设置，系统必须先复述关键信息，并要求用户明确确认。

5. 用户确认后，系统按用户选择的方式执行任务，并持续反馈成功、失败、当前状态或下一步建议。

6. 对需要长期复用的内容，例如材料参数、测试结果、生成文件、加工任务、设备连接信息，系统会保留记录，方便下次继续使用或排查问题。

#### 大模块二：语音理解与任务分发

| 功能名称 | 使用场景 | 业务逻辑（做什么、怎么做） | 关联功能 |
| :--- | :--- | :--- | :--- |
| 语音任务识别 | 用户用自然语言说“打开浏览器”“查一下设备状态” | 系统根据用户的话判断要做什么，不要求用户记复杂说法。 | 关联所有用户入口 |
| 内置语音快捷通道（NV8a） | 用户说“停”或口语询问常用状态 | 精确停止短句不等大模型；常用只读查询（含去礼貌前后缀的日常口语问法）绕过大模型直答，纯无语义思考气音静默跳过，早于最近两轮的旧工具冗长输出自动本地折叠。仍需识别成功和真实工具结果，软件停止请求不证明机器已停。 | 关联语音识别、状态查询、硬件急停 |
| Jev 语音智能筛选与提速 | 用户希望减少抢话、加快日常语音首包并过滤无关上下文 | 默认关闭，由用户在语音中心“模型”标签顶部第 3 栏“Jev 前置粗筛”显式开启（n69 起唯一开关；细项在“模型 › 对话体验”）并复用设置中的 OpenRouter API Key（模型 `typesafe/jev-1.14`）。开启后在单次请求中并发执行四项可独立开关的筛选：半截话未说完单次续听（最多 1.2 秒）与流式缓存预热、口语只读状态快答分流、6 大工具组按需剪枝（闲聊 0 工具进主模型）、长期记忆撞词过滤；内置 60 秒 LRU 缓存与 429/超时熔断回退，恒不携带任何动作授权。 | 关联内置语音、OpenRouter Jev、长期记忆 |
| 热词与耗时诊断（NV8a） | 材料名常识别错，或想知道回答慢在哪里 | 可填写有界热词；支持的识别器使用热词，不支持的不会伪称支持。最近 20 轮耗时（含 `jev_filter` 筛选分流阶段）保留在内存，诊断复制不带完整对话或音频。 | 关联本地模型、云端识别、语音中心 |
| 自然插话（NV8b） | MOSS 正在播报，用户想直接接话 | 默认关闭；需要设备端回声消除和 realtime 上行。连续说话达到配置时长后停止当前播报并识别新一句，保留开头；真实设备效果待 HW-10。 | 关联设备固件、语音中心、对话历史 |
| 第三方工具（NV9） | 希望内置语音使用自己配置的外部服务 | 在桌面语音中心添加本机 MCP 程序或 HTTP 服务；密钥单独保存不回显。默认每次调用都在电脑上批准，可以逐个禁用；不确定是否只读时不要免批准。 | 关联桌面审批、凭据、语音中心 |
| 第三方连接与记录（NV9） | 查看服务是否在线、调用过什么 | 自动心跳和退避重连，不重复执行上次操作；显示本次运行调用次数、失败数及最近时间，审批与审计持久保存。真实服务兼容性仍需逐个验证。 | 关联异常恢复、权限、审计 |
| 任务分配 | 用户一句话可能对应不同能力 | 系统判断这件事应该交给电脑操作、激光机，还是文字图片生成能力处理。 | 关联电脑操作、激光控制 |
| 缺失信息追问 | 用户没有说清设备、文件、材料或厚度 | 系统不会猜测关键条件，而是要求用户补充必要信息，例如设备位置、材料厚度、加工文件、控制方式。用户没说具体功率、速度和次数时，系统可先查材料参数库使用推荐值。 | 关联激光安全、参数推荐、任务启动 |
| 高风险动作确认 | 用户要求启动激光、切割、移动机器或修改设置 | 系统先复述文件、材料、厚度、功率、速度、次数、设备方式等关键信息，用户明确确认后才继续。 | 关联激光控制、权限管理、操作记录 |
| 严格模式 | 管理员希望语音或局域网设备不能直接让机器运动、出光 | 在本机设置 `MOSS_FUSION_STRICT=true` 后，小智或局域网设备要求开始加工、走边框、回原点等动作时，系统只生成一条“待批准请求”，必须有人在电脑上的 MOSS 桌面端批准才执行；急停、取消、降低倍率等停止类动作不受影响。默认关闭。 | 关联桌面审批、激光安全、操作记录 |

| 语音工具分级 | 管理员想知道小智能做哪些事 | 每个小智工具分为只读、生成、降低风险、运动或出光、永不开放五级；严格模式下“永不开放”的工具（打开应用、快捷键、桌面命令、删除或覆盖材料库）直接拒绝。 | 关联严格模式、能力开关管理 |
| 低风险动作快速执行 | 用户只是查询状态、打开网页、生成图片 | 系统直接执行，并把结果告诉用户，避免无意义打断。 | 关联应用打开、状态查询、图片生成 |
| 结果反馈 | 用户想知道任务是否完成 | 系统把成功、失败、失败原因、生成文件位置、设备状态等结果用自然语言反馈。 | 关联异常处理、任务记录、用户培训 |

#### 大模块三：本地电脑操作

#### 大模块四：文字图片与加工素材生成

#### 大模块八～十：Rust 版未提供的能力

Python 版曾提供摄像头查看、Home Assistant 智能家居控制和 LaserGRBL 桌面软件按钮自动点击。Rust 版没有这些工具，`ToolCatalog` 中不存在对应名称，也没有 `ENABLED_IP_CAMERA`、`HA_*`、`ONVIF_*` 环境变量。提示词、培训材料和销售说明不得把它们写成可用；如需恢复，按 [开发规范](standards.md) 的新增工具流程实现并重新登记。

| 使用说明维护 | 新员工需要知道系统能干什么 | 团队用白话字典解释每个功能的用途、风险和关联影响。 | 关联培训、交接、风险控制 |
| 安装运行说明维护 | 换电脑或新装环境时 | 团队按说明准备运行环境，确保本地助手能启动并连接小智。 | 关联本地助手启动、故障排查 |
| 高风险功能培训 | 操作人员要使用激光控制 | 团队必须说明哪些话会真正启动机器，哪些只是生成文件或查询状态。 | 关联激光安全、权限管理 |
| 变更同步 | 新增或修改功能后 | 团队同步更新功能字典、使用规则和检查流程，避免文档与实际不一致。 | 关联文档维护、质量检查 |

### 三、容易被忽略的“隐形功能”

| 隐形功能 | 为什么容易被忽略 | 白话说明 | 影响范围 |
| :--- | :--- | :--- | :--- |
| 功能存在不等于可用 | 看到项目里有某能力，不代表小智能用 | 本地命令执行需要管理员在本机开启；Python 时代的摄像头、智能家居、桌面点击能力已经不存在。 | 影响本地命令执行、培训材料 |
| 小智端和本地端分工 | 用户容易以为所有能力都在小智设备里 | 小智负责听用户说话和展示结果，本地助手负责调用电脑和本地设备。 | 影响培训、排障、部署 |
| 高风险动作二次确认 | 用户可能觉得“说了开始”就该马上执行 | 激光启动、切割、移动、改设置等必须先确认，避免误伤、误切、误动；底层发送工具也会用 `confirmed` 参数拦截未确认请求。 | 影响激光全流程 |
| 只读探测 | 查询状态和真正执行动作不是一回事 | 系统可以默认查看设备状态，但不能默认执行会改变设备状态的动作。 | 影响网络激光设备、故障排查 |
| 设备预检失败不续跑 | 用户可能开机后以为任务会继续 | 为避免用户开机瞬间机器自动执行，设备在线检查失败后，本次请求直接结束，必须重新确认启动。 | 影响串口激光、网络激光、任务启动 |
| 不自动猜设备地址 | 用户可能希望系统自己找到设备 | 出于安全和准确性，系统不会编造设备地址或串口；网络设备可以用局域网扫描发现，但仍要用户确认。 | 影响网络设备、串口 |
| 文件生成与机器启动分离 | 用户可能以为生成文件就是开始加工 | 生成图片、生成加工文件等准备动作都不出光（画板“走边框”会真实移动机器校位，属于例外）；真正启动机器需要单独确认。 | 影响文字图片、激光任务、工具路由 |
| 材料参数沉淀 | 用户可能每次都重新试参数 | 系统可以保存材料经验，让下次同类加工更快更稳。 | 影响参数推荐、正式加工 |
| 工作范围保护 | 用户只关注图片大小，不知道机器行程限制 | 系统需要拦截超出范围的任务，避免加工失败或设备风险。 | 影响文件生成、任务启动 |
| 操作留痕 | 用户只看最终结果，忽略过程记录 | 失败排查、责任追溯、培训复盘都依赖关键操作记录。严格模式下，审批的创建、批准、拒绝、过期、执行结果，以及被拦下的请求都写入本机审计记录；审计写不进去时宁可不执行。 | 影响维护、排障、安全 |
| 敏感信息隔离 | 团队容易把设备地址、密码写进文档 | 私密信息必须放在本机私密设置里，公共文档只写填写规则。 | 影响安全、交接、合规 |
| 测试不能碰真设备 | 团队容易为了验证功能直接跑机器 | 开发和维护时用 `FakeGrbl` 与回环模拟器验证，不为了测试启动真实激光或桌面操作。 | 影响质量检查、安全管理 |
| 失败提示白话化 | 晦涩错误用户看不懂 | 系统需要把失败转成“设备没连上”“文件不存在”“设置不完整”等可操作提示。 | 影响所有用户体验 |
| 角色权限边界 | 不是所有人都应该能启动激光 | 查询、生成文件、选择参数可以开放；真正启动机器应限制给可信用户。 | 影响语音权限、激光安全 |

### 四、文档维护与更新规范（给团队看的）

1. 每新增一个功能，必须补进“功能全景字典”：写清楚功能名称、使用场景、系统具体做什么、会影响哪些其他功能。

2. 每新增一个高风险动作，必须同步补进“隐形功能”和“安全规则”：说明是否需要用户确认、是否能默认执行、失败时怎么提醒。

3. 每次修改功能开关、默认参数、设备控制方式或用户说法，都要同步更新培训话术：确保运营、销售、新员工看到文档后，能准确知道“用户怎么说、系统会怎么做、什么时候不能直接做”。
