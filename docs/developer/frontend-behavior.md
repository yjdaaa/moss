# 前端行为契约

记录有代码或测试固化、改动时必须保留的前端行为，按当前 `frontend/src` 核对。改这些行为前先改本文与对应测试。

## 1. 路由与 API 基址

| 路径 | 页面 | 主要调用 |
| --- | --- | --- |
| `/` | `HomePage` | `/api/ui/runtime-config`、`/api/ui/serial-ports`、`POST /api/ui/discover-controllers`、`/api/ui/material-options`、`/api/material-lab/export`（调整库内参数时读取各厚度既有配置）、`/api/connection/check`、`/api/text-task/generate`、`/api/upload`、`/api/workflow`、`/api/safe-action`（急停 `emergency_stop`、现场移头 `relative_move`、设为工作原点 `set_origin`、解锁 `unlock`）、`/api/system/info` |
| `/draw` | `DrawPage` | `/api/draw/preview`、`/api/connection/check`、`/api/device/framing`、`/api/workflow` |
| `/material-lab` | `MaterialLabPage` | `/v1/material-lab/bootstrap`（首屏一次）、`/api/material-lab/manage` / `recent` / `export` / `preview` / `send` / `status` / `select-cell` |
| `/twin` | `TwinPage` | `/api/workflow`（`recent` / `status`）、`/preview`、`/api/connection/check`、`/api/safe-action`（`status` / `emergency_stop`） |
| `/camera` | `CameraPage`（仅桌面端） | 不走 HTTP，经 Tauri 命令 `voice_builtin_status`、`voice_builtin_start`、`voice_device_request`（`capture_photo` / `camera_frame` / `clear_camera_frame`）；进入页面不自动拍照（浏览器测试 `tests/camera.browser.mjs`，纯逻辑 `cameraState.js`） |
| `/voice` | `VoicePage`（仅桌面端） | 见第 9 节 |

路由在 `main.jsx` 按 `pathname` 前缀切换，`popstate` 同步；`/camera` 与 `/voice` 只在桌面端（`isVoiceCenterAvailable`）可进，其他环境回到工作台。应用渲染前，Tauri 内嵌页通过 `get_backend_origin` 获取实际回环端口；获取失败显示错误与重试入口，不猜测 9666。`authSession.getApiBaseUrl` 在 `127.0.0.1` 或 `localhost` 且非 Vite 端口（5173/5177/5178）时同源；独立 Vite 开发页使用默认 `http://127.0.0.1:9666`。所有请求经 `apiFetch` 附加 Bearer token，收到 401 时派发 `laser-auth-required` 事件弹出配对窗口。桌面端在渲染前还通过 `get_desktop_session` 取得桌面会话（`authSession.refreshDesktopSession`，只存内存，取不到不影响启动），`apiFetch` 与画板的请求只对本机相对路径附加 `X-Moss-Desktop-Session`；收到 403 `desktop_session_invalid` 时重新取会话并只重试一次，其他 403 不重试。浏览器与 Android 没有桌面会话。

## 2. 状态词表与归一化

实现：`src/state/statusNormalize.js`；测试：`tests/statusNormalize.test.mjs`。

- workflow 状态：`collecting`、`preview_ready`、`sending`、`completed`、`failed`、`cancelled`、`feedback_recorded`。
- job 状态：`pending`、`running`、`completed`、`failed`、`cancelled`。
- 别名归一化：`queued → pending`，`canceled → cancelled`；空值归一为 `pending`。
- 终态集合：`completed`、`failed`、`cancelled`。

发送覆盖层映射（`STAGE_MAP`，必须原样保留）：

| 状态 | 步骤 | 中心文字 | 标题 |
| --- | --- | --- | --- |
| pending / queued | 0 | 等待 / 排队 | 等待任务 |
| preparing | 1 | 准备 | 准备发送 |
| running / sending | 2 | 发送中 | 正在向设备发送 |
| completed | 3 | 完成 | 发送完成 |
| failed | 2 | 失败 | 发送失败 |
| cancelled | 2 | 已取消 | 任务已取消 |

`extractWorkflowInfo` 从 `result.workflow` 或顶层取 `status`，从 `runtime_job` 取 `job_id`，并把 `speech` / `result` 作为播报文本。

## 3. 发送进度与轮询

- 确认发送前先调用 `/api/connection/check`，再调用 `/api/workflow` 的 `confirm_send` 并携带 `confirmed:true`、`workflow_id` 与连接参数；客户端不提交快照 SHA，由服务端重算。
- 进度通过轮询 `/api/workflow {action:"status"}` 获得，显示 `send_result.lines_sent / total_lines`、`target` 与 `phase`；可信终态才停止轮询。2026-11-05：工作台生成预览后读取 G-code 走 `api/client.js::fetchPreviewText`，非 2xx 时报错“刀路读取失败”而不把错误页当 G-code；日志里的物理 SHA-256 只显示后端返回的真实值，拿不到时写“摘要不可用”，不再伪造摘要或声称门禁已通过（发送时后端仍按物理文件重算）。顶栏状态（240 ms / 3 s）与内置语音状态（对话中 140 ms）轮询经 `pollGuard.js::createPollRunner` 保证同时最多一个请求、切换间隔或卸载后丢弃旧响应。审批、工作台与标定轮询同时最多一个请求，每次 5 秒超时，结束后间隔 1 秒再查；取消后迟到结果不写入新任务。失败保留最后状态与进度，显示“状态未知、机器可能仍在运行”，继续重试，不伪造 failed。
- 主页支持 `action:"resume"` 从指定行续传（HomePage 内存态路径）。

## 4. 画板重复发送防呆

实现：`src/repeatSendGuard.js`；测试：`tests/repeatSendGuard.test.mjs`。

- 预览成功后记录响应中的 64 位十六进制 `content_fingerprint`。
