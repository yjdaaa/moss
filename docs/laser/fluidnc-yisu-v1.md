## YAML 的交付边界

同目录 `fluidnc-yisu-v1.config.yaml.example` 是故意保留无效占位值的待核验模板，
不是可安装的固件配置，不会复制到控制器或 FluidNC 源码目录。

必须先取得：

- 主板正反面清晰照片、完整型号、版本及 MCU 丝印；确认它适用这份 FluidNC 的构建目标。
- 厂家原理图或明确对应版本的引脚表：STEP、DIR、ENABLE、限位及激光 PWM。
- 电机驱动型号、细分、步距角、轴映射及方向；不能仅按“GT2 20 齿”猜步数。
- 激光模块完整型号、TTL 输入电平/极性、PWM 频率范围及使能接线。
- 实际限位开关、回零方向、门控和硬件急停接线；未核实时不生成回零/启动宏。

模板的 `Laser.speed_map: 0=0% 1000=100%` 是与当前上位机匹配的**目标配置**，
不是已读到的设备配置。它定义 S 值标尺，不证明实际光功率线性，也不能替代材料重新标定。
任何配置部署、重启、烧录或出光测试必须另行明确授权。

## 上位机行为

- 连接探测读取完整 `$$` 到终止 `ok`，检查 `$32=1` 并记录 `$10`；随后发 `$CD` 读取 YAML
  （宏、急停/故障引脚、`planner_blocks`、`must_home`），旧 GRBL 回 `error:3` 时静默跳过。连接成功不代表允许加工。
- 完整任务（含材料矩阵）发送前要求设备 `$30` 为有限正数；非 1000 时在发送流水线中按比例换算 S 值，
  原文件与 SHA 门禁不变。不写 `$30`/`$32`（FluidNC 中它们是只读代理，写入回 `error:162`）。
- 再发送 `?` 要求 Idle：拒绝 Run/Jog/Home、Hold、Door、Sleep、Check、Alarm、SD 文件运行标记，
  以及 `Pn:` 含 `E`（急停）/`F`（故障）/`D`（门）的情况，并说明是哪一个。
- 发送前剥离 `;` 与 `( )` 注释、丢弃空行，单行超过 254 字节或含非 ASCII 字符即拒绝整个作业并报行号
  （FluidNC 对超长行静默截断仍回 `ok`；≥0x80 的字节被当实时字符走 UTF-8 解码，不进入行缓冲）。
- 字符计数流控窗口（2026-11-05 修订）：`Bf:` 第二个数是此刻剩余字节而不是总容量。尚未观测时，
  `$CD` 确认是 FluidNC 的网络连接从 256 字节起步，其余（含全部串口、未知设备）从 127 字节起步
  （经典 GRBL 1.1 RX 缓冲 128 字节、可用 127）；预检 `?` 等无未确认指令时读到的 `Bf:` 即容量，
  窗口取该值 − 1，最多 1024；发送中的 `Bf:` 只能把窗口抬高到"剩余 − 1"，不能压低，也不再套用 255 下限。
  FluidNC 设备会先发 `$RI=200` 开启本通道自动上报，结束时 `$RI=0`；旧 GRBL 回 `error:3` 时静默关闭。
  `$RI` 应答 2 秒未到时补发 `G4 P0` 同步，3 秒内收齐两条应答才开始发送，否则报错且不发任何 G-code。
- 解锁 `$X` / 回零 `$H`：等 `ok` 后继续等到 Idle，`Home` 状态视为忙碌；YAML 配了 `after_unlock` /
  `after_homing` 宏时超时加倍。SD 脱机作业进行中拒绝一切顺序指令（固件会静默丢弃），只放行实时单字节。
- 文件逐行收到 ACK 后，保持任务占用，发送 `G4 P0` 同步规划器，收到 ACK 后查询 Idle。
  同步依据是 FluidNC 源码 `MotionControl.cpp::mc_dwell()` 调用 `protocol_buffer_synchronize()`。
- `lines_sent` 仅统计原文件 ACK，不包含握手、同步命令或状态查询；100% 不代表完成。
  `send_result.phase=awaiting_completion` 表示等待机器结束；只有核验通过才能 `completed`。
- 等待 ACK 时也检查取消。复位横幅（`Grbl `、`[MSG:INFO: Restarting]`、`[VER:`）、断线、报警及无法确认 Idle
  均不能被当作完成；失败不会自动重新发送文件。`failed` 可能意味着执行结果未知，不意味着机器已经停止。
- 固件在 `ALARM:N` / `error:N` 之前发的说明行（`[MSG:INFO: ALARM: ...]`、`[MSG:ERR: ...]`）会拼进报错，
  例如 `ALARM:14 (Unhomed)`；错误码表覆盖 Grbl 1–40 与 FluidNC 60–181。
- SD 脱机：`$File/ShowHash` 无返回哈希（固件未启用 HashFS）时拒绝执行，不发 `$SD/Run`；
  文件读完的 `SD: <name>: Sent` 置进度 100%，再等 Idle 才 `completed`。
- 0x18 是软件复位请求，写入成功不能证明物理停机，也不能替代独立硬件急停。

## 后续阶段

已实现：窗口流控、`$CD` 配置指纹、非 1000 标尺换算、SD 执行、mDNS 发现（主页"扫描局域网"）。
仍未实现：统一跨入口设备会话、WebSocket 直连。固件侧需开启的项见 [fluidnc-setup.md](./fluidnc-setup.md)。
当前继续使用 TCP/串口，不让前端直连硬件。外部 WebUI 同时写入设备不能被当前进程的任务锁阻止。
不要直接套用旧 Grbl_ESP32 文档的 WebSocket 端口/文本事件行为：
FluidNC 3.x 使用 `AsyncWebSocket("/")`，并把文本/二进制数据交给 `WSChannel`。

## 验证

设备单元测试覆盖完整握手 ACK、缺少终止 ACK、255/1000 标尺、异常状态、
执行同步与 Idle、同步失败、复位横幅及 ACK 等待期间取消。
API 使用响应式 fake，端到端使用回环 TCP 模拟器；不访问真实硬件。
机器 YAML、引脚、时序、限位和实际激光输出仍需资料核验及经授权的实机验收。

具体的测试数、构建产物与验证日期随每次改动记录在 `CHANGELOG.md` 对应条目的验证段，不在本文维护。
