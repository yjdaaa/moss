# FluidNC 固件侧配置说明（配合 MOSS 上位机）

日期：2026-09-20。适用固件：FluidNC 3.x。

这份文档说明：为了让 MOSS 上位机的发送、进度、急停和诊断按设计工作，FluidNC 那边需要开启什么、怎么开启，以及每一项对上位机行为的影响。所有设置都可以在不重新烧录固件的情况下，通过串口或 Telnet 发 `$` 命令完成。

## 一、必须开启的项

| 项目 | 作用 | 怎么开 | 不开会怎样 |
| --- | --- | --- | --- |
| 状态报告带缓冲字段（`$10=3`） | `?` 返回 `<Idle\|MPos:..\|Bf:15,1200>`，上位机据此自适应发送窗口 | 连上机器后发一行 `$10=3`（或 `$Report/Status=3`），回 `ok` 即生效并永久保存 | 上位机把发送窗口锁死在 256 字节，长曲线可能有微顿挫；握手摘要会提示"建议设 $10=3" |
| Telnet（端口 23） | MOSS 网络主链路 | 默认已开（`$Telnet/Enable=ON`，`$Telnet/Port=23`） | 网络模式连不上 |
| HTTP（端口 80） | SD 卡脱机模式上传文件用 `/upload` | 默认已开（`$HTTP/Enable=ON`，`$HTTP/Port=80`） | 脱机模式报"上传脱机文件失败" |
| mDNS | 主页"扫描局域网"按钮靠它找到 `fluidnc.local` | 默认已开（`$MDNS/Enable=ON`）；只在 WiFi 站点模式（连路由器）下广播，AP 模式不广播 | 扫描不到，只能手填 IP |
| 激光主轴类型 | `$32` 在 FluidNC 里是只读代理，由 `config.yaml` 里 `Laser:` 段决定 | `config.yaml` 顶层写 `Laser:` 段（见下方样例） | 握手报"$32=1 激光模式门禁未通过" |
| 功率标尺 | `$30` 同样只读，来自 `Laser.speed_map` | 推荐 `speed_map: "0=0.000% 1000=100.000%"`；写 255 也行，上位机会自动按比例换算 | 缺 `speed_map` 时 Laser 默认 0–255，上位机会自动换算，不报错 |

> `$30`、`$32`、`$100` 这类老 Grbl 编号在 FluidNC 里**写不进去**，会回 `error:162 Read-only setting`。要改必须改 `config.yaml` 再重启。上位机不会自动改这些，只读取。

## 二、建议保持的默认值

这些 `config.yaml` 顶层项 FluidNC 默认就是推荐值，请不要改掉：

```yaml
verbose_errors: true      # error:N 之前先发一行 [MSG:ERR: 原因]，上位机会把它拼进报错信息
planner_blocks: 16        # 规划器块数，10~120；越大越顺滑但占内存
use_line_numbers: false   # 上位机不依赖 Ln: 字段
```

## 三、会改变上位机行为的可选项

| `config.yaml` 项 | 上位机的反应 |
| --- | --- |
| `macros.after_unlock` / `macros.after_homing` 非空 | 解锁 `$X`、回零 `$H` 之后机器会自己跑一段 G-code。上位机收到 `ok` 后**不会**立刻放行，而是继续等到 `Idle`，超时时间加倍（解锁 30 秒、回零 240 秒），握手摘要会提示"配置了自动宏" |
| `control.estop_pin` / `control.fault_pin` 接了线 | 状态报告 `Pn:` 会出现 `E` / `F`。上位机发送前看到就直接拒绝并告诉你哪个开关被按着，不会等机器报警 |
| `control.safety_door_pin` 接了线 | 门开时状态变 `Door:x`，`Pn:` 带 `D`。发送前拒绝；发送中当作暂停继续等，关门后自动继续 |
| `start.must_home: true` | 上电就是 `ALARM:14`，必须先回零。握手摘要会提示 |

## 四、配套 FluidNC 固件的建议默认值

本仓库不包含 FluidNC 源码或 `config.yaml`。如果你维护自己的 FluidNC 构建，建议把 `$10`（`Report/Status`）的出厂默认值从 1 改为 3，让新刷的机器出厂就带缓冲字段；上游默认 1 只报位置，不报缓冲。

- 该默认值只对从未保存过 `$10` 的机器生效。已经在用的机器 NVS 里存的还是旧值，需要手动发一次 `$10=3`。
- 上位机不会自动改这些设置，只读取；无论固件默认值如何，第六节的检查清单都能确认当前值。

## 五、`config.yaml` 激光段样例

```yaml
Laser:
  pwm_hz: 5000
  output_pin: gpio.17        # 按你的主板改
  enable_pin: NO_PIN
  disable_with_s0: false
  s0_with_disable: true
  tool_num: 0
  speed_map: "0=0.000% 1000=100.000%"
  off_on_alarm: true         # 报警时自动关光，务必保留
```

## 六、一次性检查清单

连上机器后依次发送，对照返回：

```text
$10            → 应回 $10=3
$$             → 里面应有 $32=1 和 $30=1000（或 255）
?              → 应形如 <Idle|MPos:0.000,0.000,0.000|Bf:15,1200|FS:0,0>
$CD            → 应吐出整份 YAML 并以 ok 结束（上位机靠它读宏和引脚配置）
$RI=200        → 应回 ok，随后机器每 200ms 自动推一行状态；$RI=0 关掉
$SD/Status     → 用脱机模式时应回 SD card detected
```

## 七、上位机对应的行为速查

| 你在机器上做的事 | 上位机看到什么 |
| --- | --- |
| 开了 `$10=3` | 发送窗口按 `Bf:` 第二个数自适应（256～1024 字节） |
| 没开 | 窗口固定 256，握手摘要提示 |
| 跑 SD 卡文件 | 上位机只允许急停/暂停/继续/查状态，其他命令直接拒绝并提示"请先急停"（固件会静默丢弃这些命令，不回 ok） |
| SD 文件读完 | 状态报 `SD: 文件名: Sent`，进度条到 100%，再等 `Idle` 才算完成 |
| 固件没开 HashFS | 脱机模式拒绝执行（不发 `$SD/Run`），提示启用 HashFS 或改用逐行发送 |
| 机器重启（`$Bye`、断电） | 收到 `Grbl ...`、`[MSG:INFO: Restarting]` 或 `[VER:` 任一行都判为"任务中复位"，不自动重发 |
| 报警 | `[MSG:INFO: ALARM: 原因]` 那行会拼进报错，例如 `ALARM:14 (Unhomed)` |

## 八、不要做的事

- 不要通过上位机写 `$30`/`$32`/`$100`：FluidNC 会回 `error:162`。
- 不要在 SD 脱机作业进行中从网页或其他上位机发普通 G-code，固件会丢弃且不回话。
- 不要把 `Laser.off_on_alarm` 改成 `false`。
- G-code 单行不要超过 254 字节，也不要带中文；上位机发送前会拒绝，但手动用 WebUI 发的话固件会静默截断并照样回 `ok`。
