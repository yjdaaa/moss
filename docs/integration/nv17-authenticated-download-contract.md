# NV17 可信下载协议候选 v1

状态：2026-10-12，**协议候选与加密夹具已实现，尚无生产路由或设备实现**。OTA仍返回空下载URL。该任务针对小智语音设备，不是FluidNC激光控制板；不得向激光固件套用此接口。进度见[实施TODO](moss-fusion-implementation-todo.md)。

## 必须先满足的信任前置

现有OTA的Device-Id/Client-Id/型号和版本是客户端自报。数据库allowed以及OTA响应新签发的WebSocket token均不能独立证明该请求方持有真实设备身份。只加SHA-256或给URL签名也无法解决伪造设备身份与首次密钥分发问题。

设备需在用户明确授权的登记流程产生独立Ed25519密钥，私钥留设备；桌面经可信配对登记公钥、设备/client/型号和单调key revision。设备也必须经可信配置固定MOSS固件清单公钥。配对方式、板型存储/安全启动和密钥丢失恢复须结合具体固件确认；本轮不修改设备、烧录、安装密钥或扩大网络权限。没有可信配对证据时，禁止签发下载票据。

## 签名编码

使用UTF-8的紧凑JSON数组作为签名原文，固定字段顺序、长度和类型，不签可重排的JSON对象。字段为已验证的ASCII标识、规范数字段版本、整数或小写hex SHA-256。签名为Ed25519 detached signature；接收端先核对结构、长度、范围，再核验完整原文字节。协议版本不识别即拒绝，未知扩展不静默放行。

| 对象 | 签名原文数组 | 验证方 |
| --- | --- | --- |
| 固件清单 | `[1,board,version,size,sha256,artifact_revision]` | 设备，用已固定MOSS清单公钥 |
| 一次性票据 | `[1,ticket_id,device_id,client_id,board,sha256,artifact_revision,device_key_revision,expires_at]` | MOSS，用本机签名公钥并核对可信登记 |
| 请求持钥证明 | `[1,ticket_id,"GET","/xiaozhi/ota/v2/download/"+sha256]` | MOSS，用已登记设备公钥 |

ticket_id来自32字节CSPRNG。夹具TTL为60秒；生产上限和安全时钟策略需与设备实现共同确认。签名私钥不能交给Agent/LLM、放进URL或日志。票据是短时能力，必须防日志泄漏，不等于长期设备密钥。

## 服务端与设备流程

1. 桌面导入、大小/hash复核、型号/版本/revision及逐型号明确批准；凭据、设备、固件变化都作废旧票据。仍沿用现有独立权限与审批，不因设备签名免审批。
2. 仅可信配对且当前允许的设备取得签名清单及一次性票据。下载还需设备请求签名，不能只凭MAC/client头或拿到他人URL。
3. 真实HTTPS须验证证书、固定目标并拒绝重定向。仅精确GET路径，首版拒绝Range/断点重放；票据绑定设备、client、型号、文件hash和两种revision。校验全部通过后事务消费一次并创建独立下载状态。
4. 写出前验证物理文件size/hash，传输过程中复核撤销、期限及并发上限。发送后异常记录Unknown，不能自动重发或把一次性票据复活。
5. 设备必须先验证清单签名、型号、大小和完整SHA，再执行OTA；原始SHA可被攻击者替换，不能单独当发布者认证。下载完成与设备启动上报分别记录；即便有签名上报也不冒充物理刷写验收。

这是供两端实现核对的加密契约夹具，**不是已接线的固件下载服务**。后续还缺具体固件端实现、可信配对、跨语言相同字节签名fixture、持久事务/下载路由、TLS实接和实际设备恢复方案；未满足时NV17保持blocked/partial，不开启OTA。
